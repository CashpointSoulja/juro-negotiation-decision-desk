# Evals and test results

## Method
- **Fixtures:** 8 synthetic clauses (`src/engine/fixtures.ts`, `EVAL_FIXTURES`) across liability cap (F1 to F3), indemnity (F4 to F6), renewal and notice (F7) and governing law (F8). Each fixture has a playbook and a reviewer label (`expected` severity) with a written rationale.
- **Positive** = flagged (anything other than `within`). **False negative** = labelled flagged, but the engine marks it `within` (auto-accept eligible). This is the dangerous error. **False positive** = labelled `within`, but the engine flags it.
- **Regression comparison:** every fixture runs through `v1-baseline` and `v2-current`. Status per fixture: `fixed`, `regressed`, `unchanged-pass` or `unchanged-fail`.
- **Release gate:** 0 false negatives, 0 regressions, at most 1 false positive. `npm run evals` exits non-zero if the gate fails. A unit test proves the gate fails when the comparison is reversed.

### What changed from v1 to v2
| Baseline behaviour (v1) | Current behaviour (v2) | Fixture it fixes |
|---|---|---|
| Reads digits only ("2x"), so "twice the fees" goes unread and is treated as no objection | Reads word numbers. Anything still unread is **blocked**. | F2 |
| Detects an uncapped indemnity only from the words "unlimited" or "uncapped" | Also detects carve-outs: "not be subject to the limitation", "outside the cap" | F5 |
| Uses the first matching rule | Evaluates all applicable rules. Disagreement is **blocked** as a conflict. | F6 |
| A missing rule is treated as no objection | A missing rule is **blocked** | F8 |

**Known false positive, F7:** the reviewer label treats 30 days' notice as fine after a 36-month initial term. The rules don't model initial-term exceptions, so they flag it as a deviation. This is documented rather than special-cased. See ROADMAP item 2.
